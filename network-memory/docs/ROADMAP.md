## PHASE 1 報告（基礎システム）

### 完了した機能

**プロジェクト構成・データ設計**
- React 19 + TypeScript + Vite のプロジェクト（`network-memory/`）
- 型定義: Memory / Skill / 記録 / World / プレイヤーデータ
- マスターデータの読み込み・検証・参照整合性チェック（JSON を追加するだけで反映）
- Supabase スキーマ（全 16 テーブル + RLS + サーバー専用の通貨関数）。ローカル PostgreSQL で検証済み

**仮データ**
- Memory 12 種（全 7 カテゴリ・全 6 レアリティ・全 6 属性を網羅）
- スキル 42 種（アクティブ 24 / パッシブ 12 / REWRITE 6）
- 記録断片 36 件、WORLD 5 種

**起動〜LOBBY**
- 起動シーケンス → タイトル → 探索者登録 → 初期 Memory 9 体の受領演出
- LOBBY: パートナー Memory（文字送り演出）、出撃チーム、8 メニュー、システムログ、通貨表示
- 未実装メニュー（STORY / WORLD / ARCHIVE / BATTLE / SHOP）は「未実装 · PHASE n」と予定機能を明示

**MEMORY**
- 一覧: 検索（ひらがな/カタカナ・全角/半角を同一視）、分類・レアリティ・属性・お気に入りの絞り込み、11 種のソート
- 詳細: 能力（実数値 + 資質チャート）、スキル / パッシブ / REWRITE、記録（解放条件つき）、関連 Memory・入手方法・出現 WORLD、前後移動、お気に入り
- 記録を読むと関連 Memory の存在が「発見」される仕組み（所持 / 発見済み / 未発見）
- 編成: 3 プリセット × 3 枠、入れ替え、同名 Memory の重複防止、おまかせ編成、チーム名変更、出撃チーム設定、総合力・属性構成・行動順予測

**プレイヤーデータ保存**
- localStorage への自動保存（変更時・画面非表示時）、即時保存
- バージョン管理・マイグレーション枠・読み込み時の検証と修復
- 破損データのバックアップ退避、保存不可環境での警告
- JSON の書き出し / 読み込み（プレビュー確認つき）、初期化（確認入力つき）

**PROFILE / SETTINGS**
- 探索者名の変更、回収率・発見率・閲覧率、レアリティ別回収状況、所持通貨、取引履歴
- 演出の強さ（標準 / 軽量）、起動演出スキップ
- 開発者モード（全 Memory 付与・最大レベル化・通貨付与）※PHASE 2 の入手/育成ができるまでの確認用

**品質**
- 単体テスト 26 件（データ検証・ステータス・通貨・編成・検索・記録・保存/修復・reducer）
- ブラウザでの E2E 確認（スマートフォン / PC）: 新規登録〜一覧・絞り込み・検索・ソート・詳細・記録による発見・編成・リロード後の保持・未実装表示・開発者ツール。コンソールエラー 0、スマホで横スクロールなし
