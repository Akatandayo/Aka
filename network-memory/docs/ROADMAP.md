## PHASE 2 報告（Memory SYNC・戦闘）

### GDD Ver.2 への移行（PHASE 1 の変更）

| 変更前（Ver.1） | 変更後（Ver.2） |
| --- | --- |
| Memory = 仲間ユニット、3 体編成 | Memory = 主人公が同期して使う能力。メイン 1 / サブ 3 / パッシブ 2 の装備 |
| Memory の hp〜res = ユニットの能力値 | Memory の hp〜res = 装備時のステータス補正 |
| 主人公は名前のみ | 主人公に基礎ステータス・レベル・外見カラー・紹介文 |
| すべての Memory が戦闘用 | 戦闘能力を持たない Memory（探索・ストーリー用）を許可 |
| タイトル「Re:Collection」 | 「ReCollection」 |

PHASE 1 のセーブデータは自動変換されます（3 体編成 → 1 体目をメイン、2・3 体目をサブ）。

### 完了した機能

**MEMORY SYNC**
- 発見 → 接触 → 接触演出 → 同期 → 能力解放 → 一覧登録の一連の流れと専用画面
- 同期条件（探索者 Lv・特定 Memory の同期済み・ストーリーフラグ・不明）と、条件未達時の SYNC REJECTED
- 同期待ち（PENDING SYNC）一覧からの再接触、同期済み Memory の重複検出は FRAGMENT に変換

**Memory 装備**
- メイン 1 / サブ 3 / パッシブ 2、装備プリセット 3 つ、おまかせ装備
- 枠ごとの役割（ステータス補正の倍率、スキル・パッシブ・REWRITE・属性・通常攻撃）
- 同期後の主人公ステータス（BASE + MEMORY = TOTAL）、使えるスキル・パッシブの一覧
- 枠数はセーブデータで管理し拡張可能

**Battle Engine（UI から独立）**
- 主人公 1 人 vs 敵最大 3 体、SPD 順の行動、ATTACK / DEFEND / MEMORY SKILL / ITEM / REWRITE / 撤退
- SP とクールダウン、属性相性（DATA→VOID→LIFE→ERROR→DATA、ORDER⇄CHAOS）
- 状態異常 5 種、バフ・デバフ、パッシブ 7 種類の発動タイミング、敵 AI
- REWRITE: Memory ごとの発動条件、スキル強化・属性変化・ステータス変化・敵の能力への干渉・特殊スキル解放
- シード + コマンド列による完全な再現（リプレイ）、ラウンド上限
- オート戦闘（AUTO）・再生速度切替

**戦闘画面・演出**
- 流出反応（エンカウント）一覧: WORLD ごと、推奨レベル、敵、報酬、初回クリア時の Memory 反応、解放状況
- 戦闘画面: 敵・主人公の HP/SP、状態表示、ダメージ・回復のポップアップ、被弾の揺れ、戦闘ログ、対象選択
- REWRITE 専用のカットイン演出（色・カットイン文・グリッチ・画面揺れ）
- 結果画面: 経験値・レベルアップ・Memory の同期の深化・解放された記録・報酬・Memory 反応の検出
- スマートフォンではコマンドを常に画面内に表示

**成長・データ**
- 主人公の経験値・レベル、装備 Memory の同期経験値・レベル
- 新しい Memory 4 種（戦闘で検出）+ 既存 12 種の Ver.2 対応、敵 9 種、遭遇 8 種、アイテム 4 種、敵スキル 15 種
- 全 8 遭遇のバランス調整（オート戦闘のシミュレーション 60 周で全クリア、推奨レベルどおりに成長、HP 残量が段階的に減る難易度曲線）

**品質**
- 単体テスト 46 件（データ検証、装備、MEMORY SYNC、Battle Engine の決定性・リプレイ・行動順・SP/CT・状態異常・REWRITE・パッシブ・アイテム・タイムアウト、戦闘結果、v1→v2 移行、キャンペーンのバランス）
- ブラウザでの E2E 確認（スマートフォン / PC）: 装備・戦闘（手動・オート）・REWRITE 演出・結果・MEMORY SYNC（成功/拒否）・プロフィール編集・旧セーブ移行。コンソールエラー 0、スマホで横スクロールなし
- Supabase スキーマ: ローカル PostgreSQL 16 で全マスターデータの投入と RLS/権限の検証 23 件
